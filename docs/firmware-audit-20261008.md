# 입력 안정성과 개발 환경 점검 — 2026-10-08

## 사용 중 보고된 증상과 유지할 조건

- 한쪽 연결이 간헐적으로 끊긴다. 이전 수정 뒤 빈도는 줄었지만 완전히 해결됐다고
  확인하지 않았다. 현재 장치에 올라간 정확한 소스 SHA는 미확인이다.
- Base에서 평범하게 타이핑할 때 E/R이 의도치 않게 홀드 레이어로 판정되기도 한다.
  사용자는 단축키 기능을 유지하기 위해 `require-prior-idle-ms` 보호 추가를 거절했다.
- Base E/R의 tap-preferred 200ms, Mouse E/R의 tap-preferred 180ms와
  hold-while-undecided, 기존 50ms 콤보 대기를 유지한다. 키맵과 마우스 곡선을 바꾸지 않는다.
- USB HID 1ms polling, ESB 2Mbps, +8dBm, 고정 채널 2를 유지한다. 이는 설정값이며,
  모든 입력이 실제로 1kHz로 전달되거나 지연 상한이 보장된다는 뜻은 아니다.

## 점검 결과

| 경로 | 확인한 문제 / 처리 | 근거와 한계 |
| --- | --- | --- |
| RX와 탭·홀드 | 패킷 도착 시각이 처리 시각으로 바뀌어, 큐 대기가 키의 누른 시간을 왜곡할 수 있다. | 도착 시각 보존뿐 아니라 먼저 도착한 패킷보다 홀드 타이머가 앞서는 순서도 함께 다뤄야 한다. 무선 전송 이전의 지연은 이 방법으로 복원하지 않는다. |
| 주변 장치 암호 처리 | RX에서 사용하는 PSA 키를 송신 쪽 재키 설정이 동시에 폐기할 수 있는 경계를 기존 mutex로 보호한다. | 현재 독립 송신 재키 조건은 시퀀스 소진이다. 최근의 짧은 사용 중 끊김 원인이라고 단정하지 않는다. |
| 배터리 재연결 | 실제 측정값을 보관해 새 인증 세션에 다시 전달하고, 같은 값도 낮은 빈도로 갱신한다. | 키 입력 대기열을 우선하며 측정하지 않은 0%를 만들지 않는다. 송신 수락은 수신 적용 확인과 다르므로 주기 갱신도 필요하다. |
| USB 내부 복구 | nrfx 내부 큐 포화로 컨트롤러가 재초기화될 때 HID에 중단을 알리지 않아 전송 버퍼가 계속 대기할 수 있다. | DMA 중단과 오래된 완료 이벤트 폐기 뒤 RESET을 알리고, 재열거 전 제출을 차단한다. 실제 호스트의 재열거 시간은 하드웨어 시험 대상이다. |
| 화면 부하 | modifier 표시가 일반 글자 이벤트마다 동일한 색을 네 번 다시 설정한다. | 표시 상태가 같으면 그리기를 생략한다. Alt/Shift/Caps Word 변경과 새 위젯 초기화는 반영한다. |
| 조도센서 | 고정된 외부 모듈이 센서 초기화·읽기 실패 뒤에도 유효하지 않은 값을 밝기에 사용할 수 있다. | 정상 샘플만 사용하고 실패 시 마지막 정상 밝기를 유지하는 경로를 검증한다. 센서가 실제 장착됐는지는 소스 검사만으로 알 수 없다. |
| 개인키 빌더 | 기존 빌더는 컨트롤러 자체 시험과 ARM 컴파일은 검사하지만 선택한 소스의 전체 호스트 시험을 강제하지 않았다. | 개인키 주입 전에 정확한 소스 SHA/tree의 전체 시험을 수행한다. 생략·빈 시험·실패를 거부하고 결과를 비공개 산출물 manifest에 기록한다. |

기존 송신 큐 수락, 보조 FIFO, 양측 RX 할당량, 8프레임 작업 제한, ACK 응답,
재전송 타이머, 최신 키 상태 대조, USB 키/버튼 해제 복구도 검토했다.
이번 검토에서 추가로 확정되지 않은 RF 정지 원인을 가정해 큐 크기나 재시도 횟수를
늘리지는 않는다. 포화 시 완전히 사라진 짧은 탭까지 상태 대조로 복원할 수는 없다.

## 검증 원칙과 이어서 할 일

실제 C 함수를 사용하는 결정적인 큐·타이머 시험에 결함 재주입 시험을 함께 둔다.
이 시험은 MCU 실행 시간, RF 간섭, Zephyr 스케줄러, USB 호스트를 에뮬레이션하지 않는다.
전체 호스트 시험과 공개 ARM 빌드가 같은 커밋에서 통과한 뒤, 그 SHA로 세 역할의
개인키 UF2를 비공개 Actions에서 만든다. 이전에 사용한 UF2는 되돌리기용으로 유지한다.

업로드 후 확인할 사항:

1. 양손 연속 타이핑과 Base E/R 짧은 탭·의도한 홀드를 각각 확인한다.
2. Mouse E/R 속도 전환, 방향키 해제, 이동 중 왼쪽 글자로 Base 복귀를 확인한다.
3. Alt-Tab 종료, 한쪽 전원 재연결, 동글 USB 재연결 뒤 입력과 화면을 확인한다.
4. 동글만 재시작했을 때 양측 배터리 표시가 복원되는지 확인한다.
5. 끊김이 재발하면 가능하면 리셋 전에 해당 쪽과 동글 USB 로그를 수집한다.
   RX 대기 시간·포화, 송신 완료, 시계와 재시도 상태를 함께 비교한다.

빌드 성공만으로 간헐적 끊김 해결이나 실제 1k 입력 전달을 완료 처리하지 않는다.
코드·시험·이 문서는 GitHub에 보존한다. 개인키, 개인 UF2, 원시 개인 빌드 로그는
공개 소스 저장소나 Codex Cloud 개발 환경에 넣지 않는다.
