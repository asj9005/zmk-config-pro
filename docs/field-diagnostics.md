# 하루 동안 입력·연결 상태 기록하기

이 도구는 진단 펌웨어의 USB 콘솔을 **읽기만** 합니다. 타건한 글자, 키 위치,
개인키, 원본 콘솔 출력은 저장하지 않습니다. 지정한 계측 수치와 증상 분류,
PC 수신 시각만 저장합니다. Python 3와 `pyserial`이 필요하며 펌웨어 SDK는
필요하지 않습니다. 현재 PC에 설치된 Python과 pyserial을 사용합니다.

## 시작과 종료

1. 이 기능이 포함된 진단 펌웨어를 올리고 동글을 USB에 연결합니다.
   왼쪽·오른쪽의 송신 측 계측도 필요하면 해당 키보드를 USB 데이터 케이블로
   연결합니다. USB를 연결하면 배터리만 사용했을 때와 동작 조건이 달라집니다.
2. `tools/Start-FieldCapture.cmd`를 실행하거나 다음 명령을 실행합니다.

   ```powershell
   py -3 tools/collect_field_diagnostics.py --output captures
   ```

3. 화면에 `Verified console1: dongle` 등의 메시지가 나오는지 확인합니다.
   첫 스냅샷까지 약 30초 걸립니다. Verified가 없거나 스냅샷 수가 증가하지
   않으면 기록이 정상이라는 뜻이 아닙니다. 올바른 진단 펌웨어·USB 연결·
   다른 프로그램의 포트 점유를 확인합니다.
4. 평소처럼 사용합니다. 기본 24시간 뒤 종료되며, 일찍 끝내려면 창에서
   `Ctrl+C`를 누릅니다. PC가 잠들거나 종료된 동안의 기록은 얻을 수 없습니다.

`--hours 2`로 시간을 변경할 수 있습니다. 특정 콘솔을 선택할 때는
`--port COM10`처럼 지정하지만 COM 번호는 바뀔 수 있습니다. 숫자를 자동으로
가정하지 않습니다. Windows에서 VID `1d50`, PID `615e`와 현재 PnP의
인터페이스 `MI_00`을 모두 확인합니다. 현재 고정된 펌웨어의 Studio 인터페이스
`MI_03`은 명시적으로 지정해도 열지 않습니다. 콘솔을 증명할 메타데이터가 없으면
임의 포트를 시험하지 않습니다. 다른 OS는 명확한 console 인터페이스 라벨 또는
MI 메타데이터가 필요합니다.

수집기는 DTR·RTS를 false로 설정한 뒤 열며 명령, 데이터, 리셋 신호를 보내지
않습니다. 새 진단 펌웨어의 출력은 DTR 활성화를 요구하지 않습니다. 자동
재연결은 지원하지만, 원인 확인 전에 장치의 전원을 껐다 켜면 장애 상태가 사라질
수 있으므로 가능하면 증상 마커부터 남깁니다.

완성된 스냅샷이 75초 넘게 없으면 `telemetry_stale`을 기록하고 활성 콘솔 수에서
제외합니다. USB 포트가 열려 있다는 사실만으로 연결이 정상이라고 표시하지 않습니다.
다시 스냅샷을 받으면 `telemetry_resumed`을 기록합니다.

## 증상 시점 표시

화면에 출력된 실제 `capture-...` 폴더를 사용하여 다른 터미널에서 실행합니다.
증상만 지정하며 입력한 문장이나 자유 메모는 기록하지 않습니다.

```powershell
py -3 tools/collect_field_diagnostics.py --mark left_disconnect --output "captures/capture-실제폴더"
```

종류는 `left_disconnect`, `right_disconnect`, `both_disconnect`, `key_repeat`,
`mouse_stuck`, `input_delay`, `other`입니다. 한 번에 한 요청만 대기할 수 있으며,
처리 전 다시 요청하면 실패합니다. 표시는 사람이 명령을 실행한 PC 시각이며
장애의 정확한 발생 시각이나 키 입력 시각으로 해석하면 안 됩니다.

## 분석과 전달

정상 종료하거나 `Ctrl+C`로 끝내면 capture 폴더에 `report.json`이 자동 생성됩니다.
별도로 다시 분석할 때는 다음 명령을 사용합니다. 기존 보고서 파일은 덮어쓰지 않습니다.

```powershell
py -3 tools/analyze_field_diagnostics.py "captures/capture-실제폴더" --output report.json
```

조사를 요청할 때 `report.json`과 해당 capture 폴더를 함께 전달합니다.
원본 시리얼 콘솔 덤프는 별도로 만들 필요가 없습니다. capture 폴더에는
계측 JSON 파일, 수집 메타데이터, 아직 처리하지 못한 증상 마커만 있을 수 있습니다.

각 실행은 새 폴더를 만듭니다. 기록 파일은 최대 **8 MiB × 16개(128 MiB)**이며,
가득 차면 이번 실행이 생성한 가장 오래된 닫힌 기록 파일만 교체합니다.
기존 폴더나 다른 실행의 파일은 건드리지 않습니다. 스냅샷은 공통 필드를 제거해
압축된 JSON 구조로 저장하므로 30초 주기의 일반적인 하루 기록을 보관하기 위한
공간을 줄였습니다. 연결 장치 수·재연결 빈도에 따라 예전 기록이 교체될 수 있으며
보고서에 보존 구간 제한이 표시됩니다. 강제 종료 시 마지막 미완성 기록은 분석에서
제외합니다. 분석기는 최대 16개 파일, 파일당 8 MiB, 레코드당 32 KiB 및 총
500,000 레코드를 허용합니다.

## 수치의 의미와 한계

- schema 1의 72개 행을 모두 받아야 스냅샷을 저장합니다. 중복·불일치·부분
  프레임은 감지하며, 재접속·부팅 ID·역할·펌웨어 SHA가 바뀌면 분석 구간을 나눕니다.
  첫 스냅샷은 기준값이므로 그 이전의 누적 입력을 수집 기간 표본으로 세지 않습니다.
- 평균은 같은 구간의 누적 표본 수와 시간 합 차이로 계산합니다. p50/p95/p99는
  히스토그램의 **범위**입니다. 정확한 백분위 값처럼 표시하지 않습니다. 최고값은
  관측한 **해당 부팅 이후 최대값**으로, 수집 시작 이전의 사건일 수도 있습니다.
  포화 표시가 있거나 누적값이 비정상 감소한 구간은 평균·백분위에서 제외합니다.
- 32비트 일반 이벤트 카운터의 경계 부근 감소만 한 번의 wrap으로 처리합니다.
  그 외 감소는 초기화 또는 불일치로 표시합니다. 빠진 스냅샷 사이 누적 변화는
  확인할 수 있지만 정확히 언제 몰렸는지는 알 수 없습니다. 각 행은 별도로
  원자적으로 채집되며 모든 행이 동시에 채집되는 전역 상태는 아닙니다.
- `rx_queue`는 동글 또는 키보드의 수신 큐 대기 시간이며 1ms 해상도입니다.
  `rx_process`는 프레임 검증·복호화까지의 처리 시간으로 키 동작 전달은 포함하지
  않습니다. RX 표본에는 디코딩에 실패한 프레임도 포함됩니다.
  `hold_tap_*`는 보존된 중앙 입력 시각부터 최초 결정까지의 시간으로, 의도한
  180/200ms 탭·홀드 대기와 입력 지연을 포함합니다. `timer_late`는 미결정
  상태에서 실제 타이머 콜백이 처음 실행된 지연이며 RX 양보 재실행은 중복 집계하지
  않습니다. 히스토그램은 100µs부터 1초 이상까지 18개 구간을 사용합니다.
- `usb_queue`는 보고서 큐 등록부터 USB 드라이버의 쓰기 성공 반환을 관측하기까지,
  `usb_transfer`는 그 관측 이후 완료 콜백 진입까지입니다. PC가 실제 입력을
  처리한 시간이나 전체 키 입력 지연이 아닙니다. 최신 상태로 대체된 보고서와
  재동기화 보고서는 별도 `usb_queue_recovery`/`usb_queue_resync`로 집계됩니다.
  반환 전에 완료됐거나 USB 리셋으로 중단된 전송은 시간 표본에서 제외되고
  `usb_timing_discard`에 남습니다.
- `scope=0/1`은 좌/우 연결, `scope=2`는 로컬 사건입니다. 재인증·큐 포화·USB
  리셋 등의 증가가 증상과 겹치는지 살펴보되, 계측이 없다는 이유로 정상이라고
  판단하지 않습니다. PC monotonic/UTC는 **콘솔 수신 시각**으로 무선 또는 USB
  HID 지연을 직접 재는 값이 아닙니다. 서로 다른 장치 시계도 빼서 계산하지 않습니다.

`auth_restart`는 복구 경로에 들어간 횟수이며 서로 다른 끊김의 수가 아닙니다.
`handshake_timeout`도 만료 관측·복구 시도 횟수입니다. `session_established`는
중복 READY/SESSION_OK 응답을 제외한 실제 세션 확정 횟수입니다.

보고서의 `last_issue_observations`는 해당 부팅의 마지막 사건 uptime과 숫자
코드를 남깁니다. `usb_overflow` 코드는 bits23:16에 USB 상태 번호,
bits15:8에 큐의 보고서 수, bit0에 진행 중인 전송 여부, bit1에 재동기화 필요
여부를 담습니다. 키값이나 보고서 내용은 포함하지 않습니다.

휴대용 묶음에는 `field_diagnostics.py`, `collect_field_diagnostics.py`,
`analyze_field_diagnostics.py`, `Start-FieldCapture.ps1`, `Start-FieldCapture.cmd`를
같은 폴더에 넣으면 됩니다. 펌웨어나 개인키는 이 묶음에 넣지 않습니다.
