# 마우스 레이어 조정

이 설정은 공통 `config/totem.keymap`을 사용하는 BLE / ESB v2 / ESB v3 빌드에 적용된다.

## 현재 시험값

| 항목 | 값 |
| --- | --- |
| 일반 최고 이동속도 | 4500 이동 단위/초 유지 |
| 최고속도 도달 시간 | 900ms |
| 초반 기준 곡선 | 2700/900ms의 2차 곡선, 직전 2400/900ms보다 12.5% 빠름 |
| 추가 가속 구간 | 500~900ms, 기준 곡선에 최대 1800의 2차 추가 가속 |
| 이동 이벤트 주기 | 16ms |
| Acc / E 빠름 | 가속 없는 고정 속도 15750 |
| Prec / R 정밀 | 가속 없는 고정 속도 562.5 |
| E/R 탭·홀드 | tap-preferred, 180ms, hold-while-undecided |
| 콤보 | 기존 조합 및 기본 50ms 유지 |

속도는 화면의 픽셀/초를 보장하는 값이 아니다. Windows 포인터 속도 10, 포인터 가속 끔을 기준으로 감각을 맞춘다. 펌웨어는 Windows 설정을 변경하지 않는다.

이동 `&mmv`는 저장소가 관리하는 `totem,behavior-mouse-move`를 사용한다. 방향키를 누른 뒤 경과 시간을 `t` ms라 할 때, 속도의 크기는 다음과 같다.

```text
0 <= t <= 500:   2700 * (t / 900)^2
500 < t < 900:   2700 * (t / 900)^2 + 1800 * ((t - 500) / 400)^2
t >= 900:       4500
```

처음 500ms의 속도는 직전보다 12.5% 높다. 500ms에서 속도가 뛰지 않으며 이후 가속해 기존처럼 900ms에 4500에 도달한다. 실제 출력은 16ms 이벤트 주기와 정수 이동량 때문에 연속 곡선과 조금 다르다. 이상적인 16ms 주기를 가정하면 직전과 이번 모두 첫 1단위 이동은 96ms이며 최초 상한 보고는 912ms다. 처음 움직이는 지연이 줄어든다는 뜻은 아니다. 새 곡선의 실물 사용감은 아직 검증 전이다.

Acc와 Prec는 일반 가속 계산을 건너뛰고 각각 15750, 562.5의 절대 속도로 움직인다. 예전 E/R의 최종 상한을 고정값으로 잡았으며 일반 곡선을 조정해도 이 값은 바뀌지 않는다. 16ms 출력마다 각각 252, 9단위다. 스크롤은 기존 `&msc`와 레이어별 배율을 유지한다.

한 tick에서 레이어를 한 번 읽어 양축에 같은 모드를 적용하고, 최종 이동량을 input queue에 넣는다. 이후 listener에서 XY 배율을 다시 적용하지 않으므로 큐 대기 중 레이어가 바뀌어 이중 배율을 적용하는 경로가 없다. Acc와 Prec가 함께 켜지면 기존처럼 Acc가 우선한다.

모드 전환은 방향키의 눌림 값이나 일반 가속 시작 시각을 바꾸지 않는다. 방향키를 계속 누르면 시간은 Acc/Prec 중에도 흐르며, 해제하면 그 경과 시간의 일반 곡선으로 돌아간다. 예를 들어 방향키를 1초간 누른 채 Acc를 쓰다가 Acc만 해제하면 일반 최고속도 4500으로 돌아간다. 새 방향키 입력을 시작하면 일반 가속도 처음부터 시작한다. 각 모드의 소수 이동량은 별도로 누적하고, 축이 정지하면 모든 모드의 잔여값을 지운다.

고정 모드에서는 MOVE binding의 방향과 0 여부만 사용한다. Studio 등에서 MOVE 크기를 따로 바꾸더라도 고정 속도의 크기는 동일하다. 일반 모드는 기존 binding 크기를 따른다.

E 최고속도의 이동량은 16ms마다 평균 `4500 * 3.5 * 0.016 = 252`이다. Pinned ZMK의 [마우스 HID X/Y](https://github.com/zmkfirmware/zmk/blob/904c9aec8822d79149d42c8a9a77e8828eb08f5a/app/include/zmk/hid.h#L207-L215)는 signed 16bit이므로 이 값은 report 범위를 넘지 않는다. USB polling 1ms와 이동 생성 16ms는 서로 다른 주기다.

E/R의 고정값은 이전 상한 4500에 기존 AHK 근사 배율 3.5/0.125를 적용한 값이다. AHK와 이 PC에서 실측한 등가값은 아니다. 일반 모드 초반과 고정 속도를 각각 비교해 조정한다.

## E/R와 한글 입력

- E를 짧게 누르면 E를 입력하고 Base로 복귀한다. R도 같다.
- E를 누른 채 180ms 안에 I를 누르고 E를 떼면, I를 잠시 보관한 뒤 E 입력·Base 복귀 후 글자로 처리한다.
- 이미 방향키를 누르고 이동 중이면 E/R의 속도층이 켜진 다음 이동 tick부터 고정 속도를 적용한다. 새 방향키를 E/R 다음에 누르면 탭/홀드 판정 대기는 남는다.
- 단순 글자 탭일 때도 누르는 짧은 동안 속도 레이어가 켜진다. hold-preferred와 hold-while-undecided-linger는 사용하지 않는다.
- E/R 관련 콤보 판정 시간이 남으므로 지연 없는 직접 kp 동작과 같다고 보장하지 않는다.

속도층은 기존 Acc(2)/Prec(3)를 사용한다. Acc를 먼저 검사해 두 층이 모두 활성일 때 빠름을 우선한다. 기존 Acc/Prec의 왼쪽 단축키도 그대로다. 따라서 E 홀드 중 R, R 홀드 중 E가 해당 단축키로 해석될 수 있다. 속도를 바꿀 때는 먼저 이전 속도키를 뗀다. 추후 두 키의 동시 사용이 필요하면 속도 전용 레이어 분리를 검토한다.

AutoLayer_1은 공유 매크로 큐를 사용하지 않는 전용 동기식 행동이다. 키 입력·해제와 Base 전환을 호출 안에서 마쳐, 다른 매크로의 대기 때문에 다음 모음이 마우스 입력으로 해석되는 경로를 없앤다. E/R의 레이어 활성도 매크로 큐 대신 mo를 직접 사용한다.

Base 전환은 기본 `&to 0`처럼 레이어 잠금도 해제한다. 엄지의 `&to`로 켠 Mouse는 잠긴 상태이므로 `zmk_keymap_layer_to(0, true)`가 필요하다. 이전 동기식 Auto Base 구현의 `false` 인자는 문자를 입력해도 Mouse를 끄지 못하는 회귀였다. 잠긴 Mouse를 모델링한 테스트로 복귀 후 I가 글자로 처리되는지 검증한다.

## 스크롤과 AHK

첨부된 AHK의 세로 20/1줄, 가로 5/1문자를 참고했다. 당시 Windows 기준값인 세로 5줄·가로 3문자를 유지할 때 다음 배율이 대응한다.

| 모드 | 세로 휠 배율 | 가로 휠 배율 |
| --- | --- | --- |
| E | 4 | 5/3 |
| R | 1/5 | 1/3 |

E/R에서 F23/F22를 보내는 경로는 제거했다. 마우스 시험 중 기존 속도 AHK를 종료하고 Windows 기준값을 확인한다. 특히 스크립트가 실행 중일 때 종료하면 스크립트가 처음 저장했던 값을 복원할 수 있다. 다른 매크로의 수정키+F22/F23도 AHK의 와일드카드 핫키에 잡힐 수 있으므로 같이 실행하지 않는 편이 명확하다.

이 배율은 키보드가 생성하는 마우스·스크롤 입력에만 적용하며, 별도 물리 마우스나 Windows 전체 설정을 바꾸지 않는다. 앱별 스크롤 해석과 Windows 설정에 따라 감각이 달라질 수 있다.

## 미세조정

숫자는 `config/mouse-tuning.h` 한 곳에서 바꾼다. 이동 behavior와 레이어 입력 처리는 `config/mouse-tuning.dtsi`, 곡선 계산은 `include/totem/pointing_curve.h`, 이동 이벤트 처리는 `src/behavior_mouse_move.c`에 있다. `ZMK_POINTING_DEFAULT_MOVE_VAL=2700`은 초반 곡선의 기준값이며, 최종 상한 4500은 `TOTEM_MOUSE_BOOST_NUM / TOTEM_MOUSE_BOOST_DEN = 5/3`을 적용한 값이다.

- 처음 500ms를 그대로 두고 긴 이동만 조정: 기준값 2700, 도달 시간 900ms, 지수 2, `BOOST_START_MS=500`을 유지하고 `BOOST_NUM / BOOST_DEN`을 조정한다. 분자와 분모를 같게 하면 추가 가속을 끈다.
- E 고정 속도: FAST_SPEED_NUM / FAST_SPEED_DEN을 조정한다.
- R 고정 속도: SLOW_SPEED_NUM / SLOW_SPEED_DEN을 조정한다.
- 휠과 가로 휠은 별도의 분자/분모로 조정한다.
- 한글 롤링 감각이 확인되기 전에는 탭 판정 180ms와 콤보 50ms를 먼저 줄이지 않는다.

## 장치에서 확인할 항목

1. 기존 AHK를 종료하고 Windows 기준값을 확인한다.
2. 같은 빌드/키 세트의 동글·왼쪽·오른쪽을 사용한다. 같은 v3 업데이트에 settings_reset을 무조건 적용하지 않는다.
3. Mouse에서 E/R을 탭한 직후 IJKL을 빠르게 입력해 글자와 Base 복귀를 확인한다. 다른 매크로가 실행 중인 경우도 확인한다.
4. 방향키를 누른 채 E/R로 속도를 바꿨다가 놓았을 때 일반 속도로 복원되는지 확인한다.
5. E/R을 먼저 누른 경우의 180ms 판정, 기존 콤보 및 Acc/Prec 단축키를 확인한다.
6. 처음 500ms의 짧은 이동과 이후 긴 이동을 나누어 비교하고, 정밀 선택·세로/가로 스크롤 감각을 기록한다.

사용자가 보고한 간헐적인 약 1초 키 반복은 아직 해결 검증 전이다. 선행 눌림 없이 도착한 해제를 거르는 [ESB orphan-up 방어](esb-reliability-patch.md)는 소스에서 확인한 조건부 결함을 막지만, 그 결함이 실제 고착·반복의 원인이었는지는 확인되지 않았다.

공개 CI의 `ci_only_*_testkey.uf2`는 비민감한 동작 시험 전용이다. 사용감 조정 뒤 같은 소스를 비공개 개인키로 다시 빌드해 일상용으로 전환한다. 개인키 생성·UF2 제작·장치 검증은 서로 별개의 단계다.
