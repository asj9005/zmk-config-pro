# Alt-Tab 해제 신뢰성

`config/totem.keymap`의 `swapper`는 Nav 레이어의 D 위치를 짧게 누를 때
사용하는 Alt-Tab 동작이다. 기존 tri-state의 전역 Alt 토글을 전용
`totem,behavior-owned-swapper` 동작으로 교체해 자신이 추가한 Alt 참조만
해제한다. 다른 키의 물리 Alt나 sticky Alt를 일괄 해제하지 않는다.

## 사용 방식

- Nav의 D 탭으로 Alt-Tab을 시작하고, 다시 탭하면 다음 앱으로 이동한다.
  D의 Ctrl 홀드 판정과 기존 200ms 설정은 그대로다.
- D를 놓으면 Tab만 해제하고 Alt는 유지한다. **유휴 시간에 따른 자동
  해제는 없다.** 사용자가 선택한 기존 방식이다.
- 예외 위치 `2 3 7 16 17 18`(물리 E·R·I·J·K·L)은 유지한다.
  현재 Nav에서 I·J·K·L은 방향키다.
- 예외가 아닌 다른 위치의 누름/뗌, 또는 새 레이어 활성화 시 종료한다.
  Nav 엄지의 물리 해제도 예외가 아니므로 종료 조건에 해당한다.
- ESB에서 이 동작을 시작한 손의 세션을 정리할 때도 Alt-Tab을 종료한다.
  연결이 끊겼다는 판정까지 걸리는 시간 자체를 없애는 기능은 아니다.

## 보완한 경로

기존 `&kt LALT`는 전역 Alt 상태를 뒤집는다. 이미 sticky Alt 등이 켜져
있으면 시작/종료가 예상과 달라질 수 있다. 기존 tri-state는 종료 동작을
behavior queue에 넣는 데 실패해도 내부 상태를 종료로 바꿀 수 있다.
이 두 문제는 정적 RAM 점유율만으로 발생 여부를 판정할 수 없다.

전용 동작은 시작할 때 Alt 참조 하나를 추가하고 종료할 때 한 번 제거한다.
해제를 behavior queue에 맡기지 않으며, Tab은 sticky key 처리를 포함한
ZMK의 일반 keycode 이벤트 경로를 사용한다.

HID 보고 전송 실패 시에는 현재 보고를 재시도한다. Alt press/release
동작을 반복 실행하지 않는다. 재시도 간격은 25ms부터 최대 1초까지
늘어나며, USB suspend에서 단순 wakeup 요청만 성공한 경우에도 실제 보고
전송을 재시도한다. 이 타이머는 Alt 유지 시간을 제한하지 않는다.

hold-tap/combo가 이벤트를 보관했다가 재방출하는 경우를 위해 물리 입력과
재방출 입력을 모두 관찰한다. 실제 링크 순서가 필요한 순서를 만족하지
못하면 빌드를 실패시킨다. 세션 정리 이전에 보관된 swapper 활성화는
source별 시간 경계로 거부한다. 정리와 정확히 같은 millisecond의 활성화도
보수적으로 거부하며 이후의 새 입력은 허용한다.

직접 Alt 상태를 변경한 뒤에는 modifier 상태 알림을 발행한다. Prospector
modifier 위젯은 이 알림도 구독해 실제 HID 상태를 표시한다. 화면 갱신을
위한 가짜 키 입력/해제 이벤트는 만들지 않는다.

## 검증 범위

호스트 회귀 테스트는 실제 동작 본체와 ESB source 정리 함수를 컴파일해
Alt 참조 수, 중복 입력, 실패한 보고의 재시도, 지연된 입력, 화면 상태를
검사한다. Zephyr 스케줄링·무선 전송·USB 호스트 동작은 호스트 fixture만으로
보장할 수 없으므로 전체 ARM 빌드와 실물 시험을 별도로 수행한다.

실물 확인은 평소 Alt-Tab 시작 → 방향키 이동 → Nav 엄지 해제 순서와
다른 일반 키를 통한 종료, 5초 이상 유휴 상태에서 유지되는 동작,
동작 도중 시작한 손의 전원을 끄는 경우를 포함한다. 실제 Alt 해제와
동글 화면의 Alt 표시를 함께 확인한다.
