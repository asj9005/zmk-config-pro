# 클라우드에서 코드 수정하고 개인키 펌웨어 빌드하기

코드 수정과 회귀시험은 이 공개 저장소를 연결한 Codex Cloud에서 수행한다. 실제
UF2는 별도 비공개 GitHub Actions 빌더에서 기존 개인키로 만들고, 다운로드한
파일을 현재 PC에서 각 장치에 복사한다. USB 로그와 실제 무선 연결 시험은 PC와
키보드가 있는 자리에서 진행한다.

## 개발 환경

소스 저장소는 `asj9005/zmk-config-pro`이다. 현재 작업 브랜치는
`codex/esb-reliability-20260905`이며, 새 작업에서 사용할 브랜치 또는 커밋을
확인한다. 기본 브랜치가 최신 펌웨어라고 가정하지 않는다.

Codex Cloud 환경의 설치 명령은 저장소 루트에서 다음과 같다.

```bash
bash tools/cloud-setup.sh
```

Linux에서 Git, GCC와 Python 3.10 이상을 확인하고, 필요한 시스템 도구만
설치한다. `.venv-cloud`에 `west==1.3.0`을 설치한 뒤 전체 호스트 회귀시험을
실행한다. West는 manifest 기록 시험에만 필요하며, 설정 과정에서 `west update`,
Zephyr SDK 설치 또는 개인키 생성은 하지 않는다. Python 패키지의 하위 의존성은
pip가 해결하며 이 작은 개발 환경이 production 빌드 이미지와 동일한 것은 아니다.
펌웨어 의존성 SHA와 production 빌드 도구는 기존 고정을 유지한다.

환경이 준비된 뒤 검증 명령은 다음과 같다. 별도 터미널의 venv 활성화가 필요 없다.

```bash
bash tools/cloud-test.sh
```

2026-10-05 기준 전체 호스트 회귀시험은 55개다. 이후 시험 수는 늘어날 수 있다.
이 명령은 C 컴파일러가 없거나 West를 불러올 수 없으면 실패하므로 누락된 환경을
시험 통과로 보고하지 않는다. 호스트 시험은 ARM 빌드 및 실기 시험을 대체하지 않는다.

환경에 연결할 저장소는 공개 소스 저장소 하나면 충분하다. 개인키와 비공개 빌드
저장소의 접근 자격 증명은 이 개발 환경에 넣지 않는다. 설치를 위한 package manager
네트워크 접근을 사용하고, 환경의 사용 범위는 본인으로 설정한다. 공식 환경 생성·검토·
게시 절차는 [Codex Cloud 안내](https://learn.chatgpt.com/docs/cloud)를 참고한다.

아래 내용을 환경 준비 화면에서 사용할 수 있다.

> 이 저장소의 Totem/Prospector 펌웨어를 수정하고 호스트 회귀시험을 실행하는
> 작은 Linux 개발 환경을 준비해 주세요. 사용할 소스는
> `codex/esb-reliability-20260905` 브랜치입니다. 설치 단계는 저장소 루트에서
> `bash tools/cloud-setup.sh`, 이후 검증은 `bash tools/cloud-test.sh`입니다.
> 시작 안내에는 저장소의 `AGENTS.md`와 `docs/cloud-development.md`를 읽고
> 요청된 브랜치/커밋을 확인하도록 기록해 주세요. 펌웨어용 개인키나 개인 UF2는
> 가져오지 마세요. 전체 Zephyr SDK는 별도 비공개 Actions 빌더에서 사용합니다.
> 설치·전체 시험 결과를 보여 준 뒤 이 설정을 재사용할 수 있게 저장해 주세요.

## 개발에서 개인키 빌드까지

1. Cloud에서 코드를 수정하고 관련 시험과 전체 호스트 시험을 실행한다.
2. 변경을 GitHub 브랜치/PR에 반영하고 해당 커밋의 공개 테스트키 CI를 확인한다.
3. 검토할 소스의 **40자리 GitHub 커밋 SHA**를 비공개 빌더의 입력으로 사용한다.
   빌더는 같은 소스로 왼쪽·오른쪽·동글을 만들고 기존 개인키를 사용한다.
4. 비공개 빌드에서 역할별 설정·개인키 프로필·소스 SHA·UF2 해시 검증이 통과했는지
   확인한다. 공개 테스트키 아티팩트를 일상용 파일로 혼동하지 않는다.
5. 비공개 아티팩트를 PC에 내려받아 압축을 풀고 역할에 맞는 UF2를 업로드한다.
   다운로드한 세 파일은 같은 빌드 묶음으로 보관한다.

처음 클라우드 빌드를 실제 장치에서 확인할 때까지 현재 정상 작동하는 개인 UF2와
키 백업을 유지한다. 클라우드 환경 구축만으로 로컬 파일을 자동 삭제하지 않는다.
개인키 UF2 자체도 키가 포함된 비공개 파일이므로 공개 Release나 PR에 첨부하지 않는다.
